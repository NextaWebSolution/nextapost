## Getting access

Everything works inside one **workspace**, with the permissions of the person who granted access. A key or token can never do more than that person's current role allows, and approvals still apply.

- **API key** (scripts, Zapier, Make, n8n): open **Developers & AI → API keys** in the workspace and create a key. Optionally lower its role and set an expiry. The key starts with `np_` and is shown once. Send it as `Authorization: Bearer np_…`.
- **Sign-in with OAuth 2.1** (apps and AI assistants): apps register themselves (dynamic client registration or a client ID metadata document), then send the person to `/oauth/authorize`, where they pick a workspace and click Allow. Public clients only, PKCE `S256` required, refresh tokens rotate. Discovery: `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource`. People can disconnect an app any time under **Developers & AI → Connected apps**.

## Connecting an AI assistant (MCP)

NextaPost includes a Model Context Protocol server at **`https://your-site/mcp`** (Streamable HTTP, JSON responses, no sessions). It supports both the stateless 2026-07-28 protocol and earlier versions that start with `initialize`.

1. In your AI app, add a **custom connector** with the address `https://your-site/mcp`.
2. Sign in to NextaPost when the app asks, choose the workspace and click **Allow**.
3. Ask things like “Schedule three posts for next week about our new service”.

Apps that don't support sign-in can send an API key instead, as `Authorization: Bearer np_…`. Every operation below is an MCP tool with the same name and parameters. Tools that change data are marked as such, and deleting tools are marked destructive.

## REST basics

- Base URL: `https://your-site/api/v1`. `GET /api/v1` lists every operation.
- Send JSON (`Content-Type: application/json`). Media uploads also accept `multipart/form-data` with a `file` field.
- Successful responses wrap the result: `{"data": …}`. Creating returns `201`; `POST /posts/batch` returns `207` with a result per post.
- Errors: `{"error": {"code": "validation_failed", "message": "…", "details": {…}, "request_id": "…"}}`. Codes include `unauthorized` (401), `forbidden` (403), `not_found` (404), `method_not_allowed` (405), `conflict` (409), `validation_failed` (422) and `rate_limited` (429).
- Rate limit: 120 requests per minute per key or token by default (`API_RATE_LIMIT` in `.env`).
- Times are ISO 8601. A time with an offset or `Z` is exact; a time without one is read in the workspace's time zone. Responses use UTC with `Z`.
- Lists return `next_cursor` when there are more results; pass it back as `cursor`.
- To avoid overwriting someone else's change, pass the post's `version` (from `get_post`) when updating; a mismatch returns `409`.

```bash
curl https://your-site/api/v1/posts \
  -H "Authorization: Bearer np_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello from the API","channels":["CHANNEL_ID"],"publish_at":"2026-12-01T09:30:00+05:30"}'
```

## Webhooks

Create webhooks under **Developers & AI → Webhooks** (admins) or with the API. NextaPost sends a `POST` with a JSON body to your HTTPS address:

```json
{"id": "delivery id", "event": "post.published", "created_at": "2026-12-01T04:00:00Z", "workspace": {"id": "…"}, "data": {"post": {…}}}
```

| Event | When |
|---|---|
| `post.created` | A post is created |
| `post.updated` | A post is edited |
| `post.scheduled` | A post is scheduled |
| `post.unscheduled` | A scheduled post goes back to draft |
| `post.approval_requested` | A post is sent for approval |
| `post.approved` | A post is approved |
| `post.rejected` | A post is sent back with changes |
| `post.published` | A post is published |
| `post.failed` | A post fails to publish |
| `post.deleted` | A post is deleted |

Headers: `X-NextaPost-Event`, `X-NextaPost-Delivery`, `X-NextaPost-Timestamp` and `X-NextaPost-Signature: t=<unix time>,v1=<signature>`. To check a request is genuine, compute HMAC-SHA256 of `"<t>.<raw body>"` with the webhook's signing secret and compare it with `v1` in constant time. Reject requests older than 5 minutes.

```php
[$t, $v1] = sscanf($_SERVER['HTTP_X_NEXTAPOST_SIGNATURE'], 't=%d,v1=%s');
$ok = hash_equals(hash_hmac('sha256', $t . '.' . file_get_contents('php://input'), $secret), $v1) && abs(time() - $t) < 300;
```

Any `2xx` response counts as delivered. Failed deliveries are retried after 1 min, 5 min, 30 min; after 20 failures in a row the webhook is paused. Deliveries can be replayed from the delivery log.
